# Interface languages — design

## Purpose

The whole site, interface and documentation, in six languages: English (`en`), Italian (`it`), French
(`fr`), German (`de`), Spanish (`es`) and Portuguese (`pt`). Every page URL carries its language
(`/it/docs`, `/fr/read/…`, `/es/map`). A language picker in the header changes the language. A reader
with no saved choice gets their browser's language. A choice made with the picker is remembered in a
cookie, and only the picker writes it.

Success means:
- a French-speaking visitor who opens `romanmartyrology.com` lands on `/fr`, with a French interface
  and French docs;
- switching to German in the picker keeps them on the same page, and later visits to unprefixed URLs
  open in German;
- a shared `/es/…` link opens in Spanish without changing anyone's saved choice.

## Decisions

- **Languages.** `en`, `it`, `fr`, `de`, `es`, `pt`; the default is `en`.
- **URLs.** `localePrefix: "always"`: English URLs are `/en/…` too.
- **Default language.** An unprefixed URL redirects to the `NEXT_LOCALE` cookie's language if the
  cookie is valid; otherwise to the best `Accept-Language` match; otherwise to `en`.
- **The cookie.** Only the picker writes it. Opening a prefixed URL never sets or changes it.
- **Docs.** In all six languages, at `/{locale}/docs/{page}`. The fr/de/es/pt pages are draft
  translations from the reviewed English and carry a review notice.
- **Subject names.** Subjects exist in `la`/`it`/`en` only, so interface uses fall back to English for
  fr/de/es/pt, and to Latin when a label is empty. Translating subjects is a separate crmedr project.
- **Library.** `next-intl` (4.x; peer `next ^16`).

## 1. Routing and redirects

- **Pages.** Every page moves under `app/[locale]/`: the home page, `read/[edition]`,
  `read/[edition]/[mm]/[dd]`, `read/[edition]/notes`, `map`, `compare`, `review`, `scalar`, and
  `docs`/`docs/[page]`.
- **Root layout.** It becomes `app/[locale]/layout.tsx`: it validates the locale (`notFound()`
  otherwise), sets `<html lang={locale}>` and calls `setRequestLocale`.
- **Route handlers stay where they are**, unprefixed: `/api/auth/*`, `/api/mr/*`, `/api/changesets/*`,
  `/scalar/openapi.json`, `/scalar/proxy`.
- **`i18n/routing.ts`.** `defineRouting({ locales, defaultLocale: "en", localePrefix: "always",
  localeCookie: false })`. Locale-aware `Link`, `redirect`, `usePathname` and `useRouter` come from
  `createNavigation(routing)` in `i18n/navigation.ts`.
- **`i18n/request.ts`.** `getRequestConfig` loads `messages/{locale}.json`.
- **`proxy.ts`** (Next 16's name for middleware). Its matcher excludes `api`, `_next`, `_vercel`,
  `scalar/openapi.json`, `scalar/proxy` and paths with a file extension. In order:
  1. **Legacy docs URL.** `/docs/{en|it}(/{page})?` gets a 308 redirect to `/{en|it}/docs(/{page})?`.
  2. **Unprefixed path with a valid `NEXT_LOCALE` cookie.** A 307 redirect to `/{cookie}{path}`, keeping
     the query string.
  3. **Otherwise**, `next-intl`'s middleware. It detects from `Accept-Language` (falling back to `en`)
     for unprefixed paths, serves prefixed paths as they are, and adds `hreflang` alternate links. With
     `localeCookie: false` it neither reads nor writes the cookie.
- **Old URLs.** `/read/…`, `/map`, `/compare`, `/review` and `/scalar` need no special rule: step 2 or 3
  adds the prefix.
- **Edition languages stay separate.** The `Lang` type in `lib/calendar.ts` (`la`/`it`/`en`, the
  language of an edition's text) is unchanged and independent of the interface locale.

## 2. The picker and the cookie

- **`LocalePicker`.** A client component in the header's `NavMenu`, next to the sign-in controls (inside
  the hamburger panel on phones).
- **The control.** A native `<select>`, labelled by the translated "Language". Its options are the
  languages in their own names: English, Italiano, Français, Deutsch, Español, Português.
- **On change:**
  1. write `NEXT_LOCALE={code}; Path=/; Max-Age=31536000; SameSite=Lax` (and `Secure` on https);
  2. `router.replace` to the same pathname in the new locale, keeping the query string;
  3. keep the hash, except on docs pages, where anchors differ by language and the hash is dropped.
- **Sign-in and sign-out** return to the current locale-prefixed path.
- **The docs sidebar's language link is removed**; the header picker replaces it.

## 3. Messages, components and formatting

- **Message files.** `messages/{en,it,fr,de,es,pt}.json`, namespaced by component or page (`Header`,
  `Footer`, `Home`, `Bookshelf`, `Reader`, `DayHeading`, `Notes`, `Map`, `Compare`, `Review`, `Auth`,
  `Docs`, `Metadata`, …).
- **English is the source.** `global.d.ts` augments `next-intl`'s `AppConfig` with
  `Messages: typeof en`, so an unknown key fails `tsc`.
- **Server and client.** Server components use `getTranslations`; client components use
  `useTranslations`. The `[locale]` layout provides `NextIntlClientProvider` with the locale's messages.
- **Plurals and variables** use ICU syntax.
- **Metadata.** Every `metadata` export becomes `generateMetadata` using
  `getTranslations({ locale, namespace: "Metadata" })`. The localized book title, used in the header
  brand and page titles, is: Roman Martyrology, Martirologio Romano, Martyrologe romain, Römisches
  Martyrologium, Martirologio romano, Martirológio romano.
- **Dates and numbers** in the interface (the footer, review timestamps, counts) use `next-intl`'s
  formatter.
- **Map country names** use `Intl.DisplayNames([locale], { type: "region" })`.
- **Edition text is not translated.** Headings, rubrics, eulogies, footnotes, marginalia and errata stay
  in their edition's language. The edition titles on the shelf stay as printed.
- **Subject names:**
  - **edition-bound uses** (the notes page listing, the compare view's la/it/en columns) are unchanged;
  - **interface uses** (map list and markers, subject search, the docs `SampleDay`) call
    `subjectFor(subject, locale)` in `lib/subjects.ts`;
  - `subjectFor` uses the locale's label if `SUBJECT_LANGS` (`["la", "it", "en"]`) has it and it is
    non-empty, else English, else Latin, else the ID.
- **Not translated:** IDs, CRMEDR, *Martyrologium Romanum* where it names the Latin book, and Latin
  quotations and formulas.

## 4. The docs and the review notice

- **Content.** `content/docs/{en,it,fr,de,es,pt}/<slug>.mdx` (11 files each). The fr/de/es/pt files are
  translated from the reviewed English and use each language's Church terms:

| Language | Book title | Eulogy | Epact | Golden number |
|---|---|---|---|---|
| French | *Martyrologe romain* | *éloge* | *épacte* | *nombre d'or* |
| German | *Römisches Martyrologium* | *Elogium* | *Epakte* | *Goldene Zahl* |
| Spanish | *Martirologio romano* | *elogio* | *epacta* | *número áureo* |
| Portuguese | *Martirológio romano* | *elogio* | *epacta* | *número áureo* |

  Latin quotations and formulas stay in Latin.
- **Registry.** `lib/docs.ts` keeps the order of the pages and their part. Titles, descriptions, part
  names and the index text move into the messages (`Docs.index`, `Docs.parts.*`, `Docs.pages.<slug>`).
  `DocLang` becomes the site's `Locale`.
- **`<Cite>`** reads its names from the messages: Praenotanda and Ordo in en/fr/de/es/pt, Premesse and
  Rito in it.
- **`DraftNotice`.** Rendered by the docs page routes when the locale is not in
  `REVIEWED_DOC_LANGS = ["en", "it"]`. It says, translated, that the page is a draft translation awaiting
  review by native speakers, and links to `/{locale}/docs/contributing`.
- **Internal links** in content carry the locale prefix. The docs `LunarFinder` link goes to
  `/{locale}/read/…`.
- **Until the fr/de/es/pt content lands** (PR 2), those routes render the English file with the
  `DraftNotice`. A content-resolution helper falls back to `en` when a language's file is missing.
- **Copyright** is unchanged: no 2004 eulogy text, and the existing sweeps run over all six languages.

## Testing

- **`proxy.ts`** (unit tests on its handler with `NextRequest`):
  - an unprefixed path with a valid cookie gives a 307 to that locale, keeping the query;
  - with no cookie, `Accept-Language` `fr-CA,fr;q=0.9` goes to `/fr…`, and an unsupported language goes
    to `/en…`;
  - an invalid cookie is ignored;
  - a prefixed path is never redirected and never gets a `Set-Cookie`;
  - `/docs/it/lunar-table` gives a 308 to `/it/docs/lunar-table`;
  - the matcher excludes `/api/…`, `/scalar/openapi.json`, `/scalar/proxy` and `/_next/…`.
- **`LocalePicker`:**
  - it lists the six languages by their own names, with the current one selected;
  - choosing one writes the cookie with `Path=/`, a one-year `Max-Age` and `SameSite=Lax`;
  - it replaces the URL with the same path and query in the new locale, keeping the hash except on
    docs pages.
- **Messages:**
  - the six files have identical key sets;
  - each message has the same ICU arguments in every language;
  - `tsc` passes.
- **Docs:**
  - every registered page resolves in every language (falling back to `en` until PR 2, then a file
    exists in all six);
  - every internal link and anchor resolves in its language;
  - `DraftNotice` shows for fr/de/es/pt and not for en/it.
- **`subjectFor`:** the locale's label, the English fallback for fr/de/es/pt, the Latin fallback for an
  empty label.
- **Existing component tests** render through `renderWithIntl(ui, locale = "en")` and keep their English
  assertions.
- **Before each PR:** `npm run lint`, `npm test` and `npm run build`. Then a headless-browser check on the
  standalone build:
  - `Accept-Language: fr` lands on `/fr`;
  - the picker switches to `de`, and a new visit to `/` goes to `/de`;
  - opening `/es/map` leaves the cookie unchanged;
  - `<html lang>` matches;
  - nothing scrolls sideways at 375px with the picker in the phone menu.

## Delivery

1. **PR 1, interface and routing:**
   - `next-intl`, `proxy.ts`, the `[locale]` move, `LocalePicker`;
   - all six message files with the interface fully translated, including the docs titles,
     descriptions and `DraftNotice`;
   - the legacy redirects;
   - the docs at `/{locale}/docs` with en/it content and the English fallback for fr/de/es/pt.
2. **PR 2:** the docs content in fr, de, es and pt (44 files).

Each PR gets the full checks and an independent whole-branch review before merge.

## Out of scope

- Subject names in fr/de/es/pt (a crmedr issue).
- The Scalar API reference's own interface (third-party).
- Right-to-left languages.
